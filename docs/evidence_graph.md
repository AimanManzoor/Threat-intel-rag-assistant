# Source-linked CVE graph and bounded tool harness

## What is implemented
A new Evidence graph (offline) workspace in the existing Streamlit app. It renders
a source-linked graph, permits one bounded neighborhood query per receipt,
displays file/line evidence and exports a review receipt.

The bundled artifact was actually assembled with Graphify 0.9.109 build() and
to_json(), not hand-drawn or generated by an LLM. The reviewed build/export
functions match the corresponding functions in your fork at:
https://github.com/AimanManzoor/graphify/tree/d4a5b323ef8501518b82c58a05fe21b35ce24992

Graphify is a build-time dependency. The bundled graph and runtime harness work
without installing Graphify, API keys, embeddings or provider calls.

## Scope and extraction
Only the five Markdown reports in data/processed are included; processed_full
is excluded. Extract literal CVE identifiers from the first level-2 heading until
the first known Tags, Table of Contents or Related footer heading.
Repeated mentions in a report collapse to one edge with the first line reference.

The existing processed files contain related-article CVEs unrelated to the main
report. Excluding these known footer sections avoids misleading source associations.
This is a heuristic, not a universal article-body parser. Sources without supported
headings can have no extracted mentions. A mention does not establish exploitation,
causality, current vulnerability status or verified factual support.

Current snapshot: 5 reports, 3 CVE nodes and 3 mention edges (8 total nodes).
The other reports remain isolated report nodes. There are no inferred actor,
malware, campaign or exploitation relationships. EXTRACTED/confidence_score=1.0
describes a literal extraction category, not a calibrated probability of truth.

## Harness contract
Permitted plan only:

    {"tool":"graph_neighborhood","node_id":"cve:CVE-2025-20333","max_hops":2,"max_edges":2}

Python enforces the exact argument schema, one permitted tool, at most 2 hops
and 20 returned edges. Plans cannot choose paths, SQL, shell commands or providers.
A valid plan allows one tool attempt and zero provider calls per receipt.

Before traversal, load only the fixed local data/evidence_graph.json, enforce its
size/schema/profile limits, compare source hashes and independently re-extract
the expected mentions using the project's deterministic rule. Reject stale sources,
forged edges, missing expected edges, duplicate IDs and unexpected source references.
Source excerpts come from the same bytes used to compute the checked hashes.

Statuses: completed, no_matches, rejected, verification_failed.
Human review is always required. Completed means these implemented checks passed,
not that a threat claim or answer is correct. No matches does not prove absence
of a threat. Hashes detect drift; they do not authenticate a publisher or protect
against an attacker who can modify both trusted code and sources.

Traversal navigates edges in either direction while preserving their report-to-CVE
mention meaning. Two hops can expose co-mentions in one report; this is not multi-hop
RAG reasoning. The existing Q&A graph and its provider behavior remain separate.
No LLM planner is connected to this tool yet.

## Run
Launch the existing app and select Evidence graph (offline):

    python -m streamlit run app.py --server.address 127.0.0.1

Or inspect a deterministic receipt from Terminal:

    python -m src.evidence_harness --node cve:CVE-2025-20333 --hops 2 --max-edges 2

The dashboard reads its fixed artifact for display and runs the harness only on
Explore evidence. Changing a plan hides an old receipt until resubmitted.

## Optional rebuild
Use a separate build environment to keep Graphify dependencies outside the RAG
environment:

    python3 -m venv .graph-venv
    .graph-venv/bin/python -m pip install -r requirements-graph.txt
    .graph-venv/bin/python -m src.build_evidence_graph

The builder uses Graphify's directed build with dedup=False and no semantic
backend. It overwrites only the generated graph artifact. Inspect and commit the
new artifact when intentionally updating approved public source reports.

The source fingerprint is byte-sensitive, so source edits or line-ending changes
require rebuilding. Never include private operational reports, keys or work data.

## Verification
The suite grows from 27 to 41 offline tests. New checks cover footer exclusion,
source lines, bounded traversal, plan rejection, changed/forged evidence, source
preservation, schema and symlink/size limits, and dashboard use without keys/index
initialization. Existing Q&A tests remain in the same suite.
The actual Graphify build/export path was also exercised separately using the
pinned build dependency; standard regression tests do not require Graphify.

Run:

    python -m unittest discover -s tests -v

## Practical limits and next research step
File/node/edge/output limits do not impose a total execution deadline, rate limit,
service authentication or a persistent session budget. The corpus is a static local
snapshot; the original Q&A index has its own separate lifecycle. No retrieval-quality
gain, answer-accuracy gain or production security claim was measured here.

Next curate source-backed actor/malware relationships and independent reference
questions, then compare vector-only retrieval with a graph-assisted method using
the same corpus and evidence budgets. Do not claim GraphRAG improvement from a
working graph visualization alone.
